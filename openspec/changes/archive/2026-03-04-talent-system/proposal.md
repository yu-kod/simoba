## Why

レベルアップは実装済みだが、レベルが上がっても何も変わらない。タレントシステムを導入することで「レベルアップ → スキル獲得・強化 → ビルド分岐」の成長体験を作り、毎試合異なる戦略が生まれるようにする。

## What Changes

- **タレントツリーエンジン（バックエンド）**: ヒーローごとにツリー形状のタレント定義を持つ。各タレントは前提タレント（親ノード）を持ち、ポイントを消費して取得する。ロジックは全ヒーロー共通。
- **タレントポイント管理**: レベルアップ時にタレントポイントを獲得。任意のタイミングでツリーを開いてポイントを振る（蓄積型）。
- **タレント効果システム**: タレントの効果は多様 — パラメータ変更、通常攻撃の特性変化、新スキル獲得など。データ駆動で定義し、スキル差し替えにも対応できる拡張性を持つ。
- **スキルスロットシステム**: Q/E/R の3スロット。タレントで獲得したスキルを自由にスロットに割り当てる（将来的に R はウルト専用制限の可能性あり）。
- **タレントツリー UI（#35 と連携）**: Tab キーまたは HUD ボタンで開閉。リアルタイム続行（ゲームは止まらない）。未使用ポイントがあればバッジ表示。

## Capabilities

### New Capabilities
- `talent-tree`: タレントツリーのデータ構造、ポイント管理、前提条件チェック、タレント取得ロジック（サーバー権威）
- `talent-effects`: タレント効果の適用システム（パラメータ修正、スキル付与、通常攻撃変更）
- `skill-slots`: スキルスロット管理（Q/E/R への自由割り当て、スロット制約）

### Modified Capabilities
- `hero-kill-xp`: レベルアップ時にタレントポイントを付与するフック追加

## Non-goals

- 各ヒーローの具体的なタレント内容の決定（データ定義はプレースホルダーで可）
- ツリーの形状・分岐数の確定（データ駆動なので後から変更可能）
- レベル上限の変更（現在 Lv5、将来 Lv30 に拡張可能な設計にするが、今回は変更しない）
- タレント選択 UI の詳細デザイン（#35 で対応、本チケットはバックエンド + 最小限の UI）
- スキル自体の実装（Q/E/R の具体的なスキルロジック — 別チケット）

## Impact

- **Server**: `GameRoomState` にタレントポイント・取得済みタレント・スキルスロット状態を追加。タレントツリー定義は `shared/` の設定テーブル。
- **Shared**: タレントツリー定義、効果タイプ定義、スキルスロット型を追加。
- **Client**: タレントツリー UI シーン/オーバーレイ、HUD にポイントバッジ、スキルスロット表示。
- **Specs**: `openspec/specs/heroes.md`（Talent System セクション）、`openspec/specs/game-mechanics.md`（Growth System）
