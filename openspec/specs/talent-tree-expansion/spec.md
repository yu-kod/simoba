## ADDED Requirements

### Requirement: レベル上限30
`MAX_LEVEL` は 30 でなければならない（SHALL）。

#### Scenario: MAX_LEVEL の値
- **WHEN** `MAX_LEVEL` を参照する
- **THEN** 値は 30 である

### Requirement: セグメント型 XP カーブ
`XP_THRESHOLDS` は 30 エントリの累積 XP 閾値配列でなければならない（SHALL）。3セグメント構成でなければならない（SHALL）: 序盤（Lv1〜8: 増分 30〜80 XP）、中盤（Lv9〜20: 増分 100〜250 XP）、終盤（Lv21〜30: 増分 300〜500 XP）。5〜10分の試合でプレイヤーが Lv15〜25 に到達するよう調整されなければならない（SHALL）。

#### Scenario: 序盤のレベルアップが速い
- **WHEN** ヒーローが Lv1 で XP を獲得し始める
- **THEN** Lv1→Lv2 に必要な XP は 30〜50 の範囲であり、最初の1分以内にレベルアップ可能である

#### Scenario: 終盤のレベルアップが遅い
- **WHEN** ヒーローが Lv25 に到達している
- **THEN** Lv25→Lv26 に必要な追加 XP は 300 以上であり、容易には到達しない

#### Scenario: 5分の試合での到達レベル
- **WHEN** プレイヤーが5分間レーンに留まりミニオン XP を獲得し続ける（ヒーローキルなし）
- **THEN** 到達レベルは 15 前後である

### Requirement: 30レベル対応リスポーン時間テーブル
`RESPAWN_TIMES` は 31 エントリ（Lv0〜Lv30）の配列でなければならない（SHALL）。低レベルほど短く、高レベルほど長くなければならない（SHALL）。Lv0 は 0秒、Lv30 は 20〜25秒の範囲でなければならない（SHALL）。

#### Scenario: Lv0 のリスポーン時間
- **WHEN** Lv0 のヒーローが死亡する
- **THEN** リスポーン時間は 0 秒（即復活）である

#### Scenario: Lv15 のリスポーン時間
- **WHEN** Lv15 のヒーローが死亡する
- **THEN** リスポーン時間は 8〜12 秒の範囲である

#### Scenario: Lv30 のリスポーン時間
- **WHEN** Lv30 のヒーローが死亡する
- **THEN** リスポーン時間は 20〜25 秒の範囲である

### Requirement: 可変コストノード体系
タレントノードの `cost` フィールドは 1、2、または 3 の値を取らなければならない（SHALL）。ツリー内のノードはコスト別に以下の比率を目安としなければならない（SHALL）: コスト1 = 50〜60%、コスト2 = 25〜35%、コスト3 = 10〜15%。

#### Scenario: コスト1ノードの取得
- **WHEN** プレイヤーが `talentPoints >= 1` で、コスト1のノードを取得する
- **THEN** `talentPoints` が 1 減少し、タレントが取得される

#### Scenario: コスト3ノードの取得
- **WHEN** プレイヤーが `talentPoints >= 3` で、コスト3のノードを取得する
- **THEN** `talentPoints` が 3 減少し、タレントが取得される

#### Scenario: コスト3ノードでポイント不足
- **WHEN** プレイヤーが `talentPoints === 2` で、コスト3のノードを取得しようとする
- **THEN** サーバーはメッセージを無視し、状態は変化しない

### Requirement: 扇状ツリーレイアウト（下→上）
タレントツリー UI はルートノードを画面下部に配置し、上方向に分岐が広がる扇状レイアウトでなければならない（SHALL）。depth 0（ルート）は下部中央、depth が増すごとにノードが上方向に配置されなければならない（SHALL）。

#### Scenario: ルートノードの位置
- **WHEN** タレントツリー UI が表示される
- **THEN** ルートノード（prerequisites が空のノード）は画面下部中央付近に配置される

#### Scenario: 深いノードほど上に配置される
- **WHEN** depth 3 のノードが表示される
- **THEN** depth 0 のノードより上方に配置される

### Requirement: ツリー UI のパン・ズーム対応（条件付き）
ノード数が多く一画面に収まらない場合、マウスドラッグによるパン操作およびマウスホイールによるズームイン/アウトをサポートしなければならない（SHALL）。一画面に全ノードが収まる場合、パン・ズーム機能は不要である（MAY omit）。

#### Scenario: ノードが一画面に収まらない場合のパン
- **WHEN** ツリーのノード数が画面に収まらず、プレイヤーがマウスドラッグする
- **THEN** ツリー表示がドラッグ方向にスクロールする

#### Scenario: ズーム操作
- **WHEN** プレイヤーがマウスホイールを回す
- **THEN** ツリー表示が拡大または縮小される

#### Scenario: ノードが一画面に収まる場合
- **WHEN** ツリーの全ノードが画面内に収まる
- **THEN** パン・ズーム機能がなくても全ノードが視認・操作可能である
